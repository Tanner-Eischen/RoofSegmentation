# Dataset decision record: improving roof/building IoU

## Recommended immediate acquisition: WHU aerial buildings

- **Original publisher:** https://gpcv.whu.edu.cn/data/building_dataset.html
- **Third-party downloadable mirror:** https://huggingface.co/datasets/giswqs/WHU-Building-Dataset
- Already paired RGB tiles and **binary building masks**, 512 x 512 at 0.3 m
  GSD. The original publisher describes geographically distinct train/val/test
  areas. The mirror advertises 5.25 GB and a split count that differs from
  the original dataset description. These differences must be recorded.
- The retrieved mirror describes **5,732 train / 1,228 val / 1,228 test** tiles.
  The publisher describes **4,736 train / 1,036 val / 2,416 test** tiles in
  specified spatial areas. Mirror filenames are renamed and supply no mapping
  to original tile locations. Its directory splits alone do not establish
  geographic independence. Report a mirror baseline as a mirror-partition
  result, with spatial independence unverified.
- Best first choice to get an end-to-end *authentic* training and evaluation
  run quickly. It is not a domain-generalization benchmark.
- **Important:** the mirror advertises CC BY 4.0; the publisher's present
  dataset page does not clearly specify redistribution terms. Verify the
  license for the exact copy you use before republishing any imagery.

## Keep existing AIRS data processing, but isolate as separate benchmark

- AIRS uses extremely fine 7.5 cm Christchurch roof imagery and labels.
- Existing `scripts/prepare_airs.py` has two different problems: (a) its tile
  names are `airs_<source>_<col>_<row>.png` while its leakage regular expression
  treats the numeric fields as a **macroblock** identifier, so its assertion
  does not reliably enforce the intended group; and (b) neighboring macroblocks
  can be allocated to different splits without a spatial buffer.
- If using AIRS, repair group identifiers and introduce buffered geographical
  holdouts before relying on any new test metric. The provided WHU importer
  deliberately preserves supplied WHU partitions rather than trying to repair
  AIRS in-place.
- Mixing AIRS and WHU is not automatically more data diversity: both are
  Christchurch-based and some geography may overlap. Check geographic overlap
  and annotation definitions first.

## Better domain-generalization addition: SpaceNet 2

- https://spacenet.ai/spacenet-buildings-dataset-v2/
- Four cities: Las Vegas, Paris, Shanghai, Khartoum. WorldView-3 imagery,
  georeferenced building footprints (GeoJSON).
- Material differences in sensor, illumination, roof size, climate, and urban
  form give a much better transfer test than more neighboring Christchurch chips.
- SpaceNet 2 imagery is big (Paris 5.3 GB, Vegas 23 GB per publisher) and the
  official page states an AWS account is required. Our `geopairs` importer
  rasterizes its GeoJSON polygons onto the TIFF affine grid.
- Use at least one **completely withheld city** for out-of-domain testing. Report
  WHU within-domain and SpaceNet external-domain metrics separately.
- The current frozen-data evaluator accepts the dataset bound to the training
  checkpoint. A separately defined external evaluation mode is needed before
  running this transfer experiment; changing its manifest is deliberately rejected.
- Publisher lists CC BY-SA 4.0 for SpaceNet 2; follow attribution/redistribution
  rules, and do not misrepresent visible roof extents as cadastral footprints.

## Optional broader coverage: OpenEarthMap

- https://zenodo.org/records/7223446
- 5,000 images over 97 regions / 44 countries, land-cover masks with a building
  class. Multi-class masks cannot simply be treated as binary 0/255 without
  confirming the class index, color encoding, split policy, and license.
- This is a useful **later** transfer test but not the quickest first dataset.

## What label changes increase IoU legitimately?

- Fix incorrectly paired masks and images, split contamination, offset masks,
  inconsistent non-roof inclusion, and mismatched resolution/crops.
- Include true roof-free background examples in train/validation/test; avoid
  removing every empty tile from training.
- Confirm split and source provenance before quoting numbers. Train/val/test
  must not have adjacent-overlap chips shared across splits.
- Use same spatial input size and label semantics within a benchmark; don't
  combine building footprints and roof materials into one target.
- Evaluate on independent scenes, not merely individual training patches.
- No annotation should be generated by the model and silently added as
  independent ground truth.

## Existing repository findings relevant to your comparison

- `train_v2.py` originally chooses the 'best' checkpoint by val IoU@0.5, but
  chooses a threshold from the *last epoch* model and applies it to that saved
  best checkpoint. The upgrade tunes the best checkpoint itself.
- `evaluate.py --split test --sweep` can tune on test and then report that same
  test set, invalidating it as final held-out performance. Our new evaluator
  never tunes on test.
- Existing `dataset.py` skips nonexistent image/mask pairs. The upgrade fails
  on missing masks and unexpected label values rather than quietly shrinking
  the dataset.
- Existing CI relies on mocked inference and does not measure real IoU.

## Interpretation of IoU

A meaningful IoU improvement requires holding dataset version, geographical
split, preprocessing, evaluation target, and threshold policy fixed. If you
change labels and splits, the new result is a new benchmark, not an improvement
of the old 0.86 figure. Do not claim a performance change without comparable
held-out tests.
